# Task 1 - HaloPSA and IT Glue API client review

Scope: app/Services/Halo/HaloPsaClient.php, app/Services/ItGlue/ItGlueClient.php, all callers, and credential storage.
Method: static read of code (read-only), compared with vendor docs. IT Glue docs were fetched live (https://api.itglue.com/developer/, ~390k chars; I read chars 0-300000 which covers intro, pagination, rate limits, Flexible Assets; Organizations section NOT read). The HaloPSA apidoc (haloitsm.com/apidoc/info 404; halo.haloservicedesk.com/apidoc/info is a JS shell) could not be read; only the Halo guide https://usehalo.com/halopsa/guides/1499/ was read (auth only). See "Unverified claims".

## Summary

Callers: HaloPsaClient is used by Api/TicketController, TicketController, Admin/SyncController (partly), Admin/ClientsController, Admin/SettingsController. ItGlueClient is used by Admin/ClientsController (itglueSearch, syncDomainsToItglue) and Admin/SyncController (~L1004). RunSyncTaskCommand (scheduler) calls SyncController methods directly.

Main problems:
1. There is no retry/backoff/429 handling in either client, and no pagination loop in the client classes (Halo assets/clients/tickets, IT Glue organisations are single-page fetches), so data is silently truncated.
2. Failures are swallowed in several places in ways that cause wrong writes (IT Glue find returns null on any error -> duplicate creates; Halo token failure returns null into withToken()).
3. Halo and IT Glue logic is duplicated in SyncController using the Http facade with different token cache keys, no tenant param, and a different base_url convention than HaloPsaClient.
4. Secrets are stored as plaintext JSON in `settings`, the IT Glue key is rendered in clear in the settings form, and settings diffs (including api_key old/new) go to the audit log.
5. Halo sync appends to asset notes on every run (unbounded growth); IT Glue PATCH deletes unspecified traits.

TLS: no `verify` override anywhere in app/ (grep found none for Halo/IT Glue), so Guzzle/Laravel defaults (verification on) apply. Good.

## What conforms to the docs

- IT Glue: `x-api-key` header, `application/vnd.api+json`, `page[size]` syntax (Guzzle encodes nested arrays as `page[size]`), default base `https://api.itglue.com`, `filter[organization-id]`, `filter[flexible-asset-type-id]`, `filter[name]`.
- Halo: OAuth2 client credentials, scope `all`, `/auth/token` (via configurable auth_server + `/token`), Bearer token, token cached with `expires_in - 60`, one refresh on 401, POST array body for Asset create/update.
- TLS verification not disabled anywhere in the reviewed code.
- Secrets are not logged by the clients' own Log calls (api key/headers not included); Halo masks api_key in the form.

## Unverified claims

- All Halo API behaviour except auth was NOT verified against live docs: the apidoc pages were 404/JS-rendered. Unverified: pagination param names (`pageinate`, `page_size`, `page_no` vs the `count`/`page`/`pageSize` the code uses), response wrappers and `record_count`, `includeinactive`, Asset query params (`client_id`, `assettype_id`, `search`), POST array-body contract for Asset/Tickets/Actions, content-type `application/json-patch+json` for Actions, rate limit values (I believe Halo throttles per-minute and returns 429 but have no citation). Findings H1-H3, M3-M7, L5 rely on this and on general knowledge; they should be confirmed at `<instance>/apidoc`.
- Verified live (api.itglue.com/developer): regional URLs, x-api-key, Content-Type rule, max page size 1000, 3000 req/5 min and 429, filter syntax, Flexible Assets list/create/update tables and the "traits you don't specify will be deleted" warning. Not read: Organizations section (chars >300000), so M8's server-side `filter[name]` suggestion and `meta.total-pages` (used by SyncController) are unverified; docs do not describe retry/backoff.
- Halo token endpoint `{instance}/auth/token`, scope `all`, Client Credentials: confirmed in usehalo.com guide 1499; the `tenant` query param is from a web search snippet (n8n docs), not Halo's own page.
- H8: I did not read AuditLogger to confirm there is no redaction downstream.
- M11: whether IT Glue accepts the dashed attribute names/`flexible-assets` type was not tested.
- Runtime behaviour (e.g. actual Halo default page size) was not tested; no network calls to vendors were made with credentials.
